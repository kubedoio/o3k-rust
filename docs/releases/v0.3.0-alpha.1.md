# O3K v0.3.0-alpha.1 — release candidate draft

This document is a release-candidate checklist, not a claim that the release
has shipped. The release gate remains blocked until real libvirt E2E, failure
recovery, clean Ubuntu and Debian installation artifacts, measured benchmark
data, and an approved human-review artifact bound to the candidate commit all
report the required status.

## What changed since v0.2.0-alpha.2

v0.3.0-alpha.1 is the first operator-diagnostic milestone (#617): the `o3k`
operator CLI ships with its first subcommand, `o3k doctor`, a strictly
read-only, secret-safe diagnosis of the complete TestLab stack:

- `sudo o3k doctor` (human, sectioned) and `sudo o3k doctor --json` (stable
  machine contract, `contracts/o3k-doctor-output.schema.json`) with 31 checks
  across Host, Services, Control plane, Database, Identity, Compute agent,
  Libvirt/KVM, Networking/DHCP, Cloud/API, Security boundaries, and Installed
  release; every check reports PASS/WARN/FAIL/NOT_APPLICABLE with a stable
  check ID and safe read-only next commands;
- doctor is read-only by construction: read-only SQLite, state-query-only
  system commands, and no repair path (`o3k repair` stays a separate future
  feature);
- the compute agent self-reports its live identity (agent id, epoch, software
  version, capabilities) on the loopback `/readyz` for stale-epoch and
  capability diagnosis;
- the installer now also installs the release `manifest.json` and bundle
  `SHA256SUMS` (as `/usr/local/share/o3k/release-manifest.json` and
  `SHA256SUMS`) so doctor can verify the installed version and binary hashes;
- deterministic negative-matrix evidence: per-check unit tests plus a rootless
  process-level test driving 22 sandbox classifications through the real
  binary.

## Planned contents

- x86_64 `o3kd`, `o3k`, and `o3k-compute` artifacts built on the Debian 12
  (bookworm, glibc 2.36) release baseline so the same binaries execute on both
  advertised targets (Ubuntu 24.04 and Debian 12); the glibc floor is enforced
  by `packaging/check-glibc-baseline.sh` in `make-release.sh` and
  `verify-release-bundle.sh`;
- release assets: `install.sh`,
  `o3k-0.3.0-alpha.1-linux-x86_64.tar.gz`,
  `o3k-0.3.0-alpha.1-linux-x86_64.tar.gz.sha256`, `o3kd`, `o3k`,
  `o3k-compute`, `SHA256SUMS`, `sbom.spdx.json`, `manifest.json`;
- profile-aware installer, diagnostics, reset, purge, and uninstall commands;
- SBOM, dependency/license policy result, checksums, and provenance manifest;
- OpenStack CLI/clouds.yaml example and CirrOS walkthrough;
- compatibility matrix, security model, architecture, upgrade/rollback
  boundaries, and known alpha limitations.

No production, HA, full-OpenStack, security-group, Cinder, or CellHV-readiness
claim is made. Create a tag only after `packaging/release-gate.sh` reports
`status: ready` with `--source-commit` and `--human-review`; the gate does not
generate approval or substitute for the reviewer's judgment.
